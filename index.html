Overview

This assignment focused on Bézier evaluation, halfedge mesh operations, vertex normals, and subdivision surfaces.

I first implemented de Casteljau subdivision for Bézier curves and extended the same idea to Bézier surfaces. I then implemented area weighted vertex normals for smooth shading, followed by local halfedge operations for edge flipping and edge splitting.

Using those mesh operations, I implemented Loop subdivision and tested how repeated subdivision changes both topology and geometry. I also explored how the initial triangulation of a cube affects the resulting limit surface.

For extra credit, I extended edge splitting and Loop subdivision to support boundary meshes, and I implemented sqrt(3) subdivision for closed triangular meshes.

Throughout the assignment, I tested both the numerical behavior of the algorithms and their visual results on the provided meshes.

One of the most interesting things I learned was how strongly subdivision depends on mesh connectivity, not just vertex positions. Small changes to the initial triangulation can produce noticeably different limit surfaces.

Part 1: Bézier Curves with 1D de Casteljau Subdivision

Implementation

I implemented one step of de Casteljau subdivision in BezierCurve::evaluateStep. Given a set of control points and a parameter t, the function linearly interpolates each adjacent pair of points using

\[p_i' = (1-t)p_i + t p_{i+1}\]

If the input contains n points, one call produces n - 1 new points. Repeating this process eventually reduces the control polygon to a single point on the Bézier curve.

For my custom example, I used six control points:

(0.100, 0.200), (0.200, 0.850), (0.350, 0.150), (0.550, 0.800), (0.750, 0.250), (0.900, 0.650)

Starting from six control points, the successive de Casteljau levels contain:

6 → 5 → 4 → 3 → 2 → 1 points.

Results

The intermediate interpolation levels show how the original control polygon is gradually reduced until only one evaluated point remains. The final point lies on the completed Bézier curve.

Changing t changes where the evaluated point lies along the curve, while changing one of the original control points changes the shape of the curve itself. The construction updates accordingly because every interpolation level depends on the positions of the previous level.

Visual Verification

I manually verified the custom six point curve in the viewer by stepping through every de Casteljau level using E. I also enabled the completed Bézier curve using C, moved one of the original control points, and changed t using the scroll control.

The expected reduction from six points to a single final point was visible at each step, and the final evaluated point remained on the completed curve.

Part 2: Bézier Surfaces with Separable 1D de Casteljau

Implementation

I extended the 1D de Casteljau evaluation from Part 1 to evaluate Bézier surfaces.

The surface is represented by a grid of control points. I first evaluate each row of the control grid as a Bézier curve at parameter u. This produces one intermediate point from each row. I then evaluate those intermediate points as another Bézier curve at parameter v.

So the surface evaluation is performed in two stages: evaluate every row at u, then evaluate the resulting points at v.

The implementation uses three functions:

BezierPatch::evaluateStep performs one interpolation level in 3D.

BezierPatch::evaluate1D repeatedly applies de Casteljau subdivision until only one point remains.

BezierPatch::evaluate first evaluates each row at u, then evaluates the resulting points at v.

Results

I tested the surface evaluator numerically using asymmetric control grids and several values of u and v. Using asymmetric inputs was useful because it makes an accidental swap between u and v easier to detect.

The implementation also successfully evaluated the supplied Bézier teapot model.

Visual Verification

Everything stayed connected as I moved around the model, and I did not notice any strange gaps, spikes, or missing pieces.

Part 3: Area Weighted Vertex Normals

Implementation

I implemented area weighted vertex normals in Vertex::normal.

For each vertex, I iterate around its one ring neighborhood using halfedges. For every adjacent non boundary triangle, I compute the face normal using the cross product of two triangle edges. I use the unnormalized cross product so that larger triangles contribute more to the final vertex normal.

I then sum the neighboring face normals and normalize the result.

\[ \mathbf{n}_v = \frac{ \sum_{f \in N(v)} \mathbf{n}_f }{ \left\| \sum_{f \in N(v)} \mathbf{n}_f \right\| } \]

Boundary faces are skipped when accumulating the normal.

Results

I compared the supplied teapot using flat shading and smooth shading.

With flat shading, the individual triangle faces are clearly visible. With smooth shading enabled, the surface looks much smoother because the vertex normals are interpolated across neighboring triangles.

Visual Verification

In the flat shaded rendering, the individual triangle faces are clearly visible, especially across the body, lid, spout, and handle of the teapot. In the smooth shaded rendering, these faceted transitions are greatly reduced, and the surface appears much smoother and more continuous. This matches the expected effect of area weighted vertex normals.

Part 4: Edge Flip

Implementation

I implemented edge flipping in HalfedgeMesh::flipEdge.

For an interior edge shared by two triangles, I first identify the six halfedges around the local neighborhood and the four vertices involved. The original diagonal is then replaced by the opposite diagonal while keeping the same vertices, edges, and faces.

The operation only rewires the local halfedge connectivity. No new mesh elements are created or deleted. I update the next, twin, vertex, edge, and face relationships for the affected halfedges, and I also update the representative halfedge pointers stored by the affected vertices, edges, and faces.

Boundary edges are rejected and left unchanged.

Debugging and Verification

The main challenge was making sure every pointer in the local neighborhood was updated consistently. A single incorrect next, vertex, or face assignment can leave the mesh looking almost correct while still corrupting the halfedge structure.

To make this easier to debug, I treated the flip as a strictly local operation and explicitly tracked the six halfedges surrounding the two triangles before performing any rewiring. I also tested repeated flips and checked that the mesh connectivity remained valid after each operation.

The implementation was tested on many interior edges, including repeated flips on the teapot mesh, without changing the number of vertices, edges, faces, or halfedges.

Visual Verification

I flipped several interior edges on the teapot and compared the mesh before and after. The teapot itself kept the same overall shape, but I could see the triangle layout change where I performed the flips. I also checked the edited area for anything obviously broken, and I did not see any holes, detached faces, or other visible problems.

Part 5: Edge Split

Implementation

I implemented edge splitting in HalfedgeMesh::splitEdge.

For an interior edge shared by two triangles, the operation inserts a new vertex at the midpoint of the original edge. The two original triangles are then replaced by four triangles by connecting the new midpoint vertex to the two opposite vertices.

The implementation updates the local halfedge connectivity and creates the additional mesh elements needed for the split. For an interior edge split, the mesh gains one vertex, three edges, two faces, and six halfedges.

\[ v_{\text{new}} = \frac{v_0 + v_1}{2} \]

I also preserve the edge metadata needed later for Loop subdivision. The two halves of the original edge remain marked as old edges, while the newly created edges connecting the midpoint to the opposite vertices are marked as new edges.

Debugging and Verification

The main challenge was rewiring all of the local halfedges consistently while also preserving valid representative halfedge pointers for the affected vertices, edges, and faces.

I verified the implementation by checking the expected element count changes after each split and by repeatedly splitting interior edges on several meshes. The resulting meshes remained connected and valid after repeated operations.

Visual Verification

I tested edge splitting on several interior edges of the teapot. After the splits, new vertices and smaller triangles were clearly visible in the edited region while the overall shape of the teapot remained unchanged. I then performed several edge flips on the subdivided region and confirmed that the local triangulation changed without introducing visible holes, disconnected faces, or other mesh corruption.

Part 6: Loop Subdivision for Mesh Upsampling

Implementation

I implemented Loop subdivision in MeshResampler::upsample.

The algorithm is performed in several stages so that the positions computed from the original mesh are not affected by topology changes made later in the process.

First, I compute the new positions of all original vertices. For an interior vertex of degree n, I use the Loop subdivision weight

\[ \beta = \begin{cases} \frac{3}{16}, & n = 3 \\ \frac{3}{8n}, & \text{otherwise} \end{cases} \]

and compute

\[ p' = (1 - n\beta)p + \beta \sum_{i=1}^{n} p_i \]

where p is the original vertex position and the p_i values are the positions of its neighboring vertices.

For every original interior edge with endpoints A and B, and opposite vertices C and D, I compute the position of the new edge vertex as

\[ p_{\text{edge}} = \frac{3}{8}(A+B) + \frac{1}{8}(C+D) \]

After computing all new positions, I split every original edge exactly once. I then flip each newly created edge that connects one original vertex and one new vertex. Finally, I update all vertex positions using the values calculated before modifying the topology.

This ordering keeps the geometric calculations based on the original mesh while allowing the split and flip operations from the previous parts to be reused.

Results

Repeated Loop subdivision increases the number of triangles while smoothing the mesh. Sharp corners and edges gradually become rounded, and the mesh approaches a smoother limit surface.

I also compared subdivision on the original cube with subdivision after preprocessing the cube. Because the original cube triangulation is asymmetric, repeated subdivision can produce visible asymmetry. Splitting the face diagonals before subdivision gives the cube a more symmetric initial connectivity and produces a more symmetric result.

I also experimented with additional edge splits along one physical cube edge before subdivision. This increased the local sampling density and noticeably changed the resulting surface after repeated subdivision, showing that Loop subdivision is sensitive to local mesh connectivity and sampling density.

Visual Verification

I compared the original cube, a cube with all face diagonals preprocessed, and a cube with additional sampling along one physical edge. The untreated cube became progressively smoother after each Loop subdivision step, but its asymmetric triangulation produced a noticeably asymmetric rounded shape. After preprocessing all six face diagonals, the subdivided result appeared much more symmetric. The additional edge sampling experiment produced a clear local deformation after repeated subdivision, showing that the Loop limit surface is sensitive to mesh connectivity and local sampling density.

Extra Credit 1: Boundary Edge Splitting

Implementation

I extended HalfedgeMesh::splitEdge to support edges on a mesh boundary.

For a boundary edge, the split inserts a new vertex at the midpoint of the original edge. The single adjacent interior triangle is divided into two triangles, while the boundary loop is updated so that the original boundary segment becomes two boundary segments.

The operation preserves the existing virtual boundary face and updates the local halfedge connectivity without creating an additional boundary face.

For one boundary edge split, the mesh gains one vertex, two edges, one interior face, and four halfedges.

The new vertex is placed at the midpoint of the original boundary edge.

Verification

Extra Credit 2: Loop Subdivision on Boundary Meshes

Implementation

I extended Loop subdivision so that it also works correctly on meshes with open boundaries.

For an original boundary vertex with neighboring boundary vertices a and b, I update its position using

\[ p' = \frac{3}{4}p + \frac{1}{8}(a+b) \]

For a boundary edge with endpoints A and B, the new edge vertex is placed at the midpoint:

\[ p_{\text{edge}} = \frac{A+B}{2} \]

Boundary edges are preserved during the subdivision process and are not flipped. Interior edges continue to use the standard Loop subdivision rules.

This allows open meshes to be refined while keeping their boundary loops connected.

Verification

I tested the boundary aware Loop subdivision on the open beetle mesh. I applied multiple subdivision steps and checked that the wheel arches, window openings, and other open boundaries remained intact.

The mesh refined successfully without introducing visible holes, disconnected components, or broken boundary loops.

Visual Verification

After each round, the mesh became denser and smoother while the wheel arches, window openings, and other open boundaries remained connected. I did not observe any tearing, unintended closure of the boundary loops, or disconnected geometry.

Extra Credit 3: sqrt(3) Subdivision

Implementation

I implemented sqrt(3) subdivision in MeshResampler::upsampleSqrt3.

For each original triangle, I insert a new vertex at the face centroid. I then reconnect the mesh so that each original triangle is divided into three smaller triangles.

The original vertices are repositioned using a valence dependent smoothing weight. For a vertex of degree n, I use

\[ \alpha_n = \frac{ 4 - 2\cos\left(\frac{2\pi}{n}\right) }{9} \]

and update the original vertex position using

\[ p' = (1-\alpha_n)p + \frac{\alpha_n}{n} \sum_{i=1}^{n} p_i \]

where p is the original vertex position and the p_i values are the positions of its neighboring vertices.

The implementation is restricted to closed triangular meshes. Open meshes and non triangular inputs are left unchanged.

Verification

I tested sqrt(3) subdivision on several closed triangular meshes and across a range of vertex valences. Repeated subdivision increased the triangle density while preserving valid connectivity.

I also compared the resulting topology and smoothing behavior against Loop subdivision on the same cube input.

Visual Verification

I applied sqrt(3) subdivision to the cube for multiple rounds. After the first round, each original triangle was replaced by a denser centroid based triangulation. After three rounds, the surface became much smoother and more rounded while remaining connected. I did not observe any holes, disconnected faces, or other visible topology errors.

Reflection

The most challenging part of this assignment was working with halfedge connectivity. Edge flips and edge splits are local operations, but they require every affected pointer to be updated consistently. A small mistake can leave the mesh looking reasonable while still corrupting the underlying topology.

Loop subdivision made the relationship between topology and geometry especially clear. The cube experiments showed that subdivision does not depend only on vertex positions. The initial connectivity and local sampling density can significantly affect the final shape.

The extra credit boundary work also made the distinction between interior and boundary rules much more concrete. Boundary meshes need different vertex update rules and different handling of edge operations in order to remain valid.

Overall, the assignment helped connect the mathematical definitions of curves and subdivision with the practical details required to maintain and modify a halfedge mesh implementation.
